## Definition of Skill Repository

A skill repository is a managed collection of reusable skills available to an AI agent for performing different tasks and subtasks. It can contain both pre-installed skills supplied as part of the agent’s default capabilities and custom skills that have been subsequently developed, tested, validated, and approved for reuse. Rather than requiring the agent to consider every available skill directly during every task, the repository provides an organized source from which a task-relevant subset of skills can be retrieved. For a skill repository $\mathcal{S}={s\_1,s\_2,\ldots,s\_n}$, where $\mathcal{S}$ (skill repository) represents the complete collection of available skills and each $s\_i$ (reusable skill) represents an individual skill, a new task $\tau$ (target task) can be used as the basis for task-aware skill retrieval. Retrieval may use skill metadata, semantic matching, keyword or metadata search, capability matching, constraint filtering, ranking, or combinations of these methods to derive $\mathcal{S}\_{\tau}\subseteq\mathcal{S}$, where $\mathcal{S}\_{\tau}$ (task-relevant skill set) contains the skills considered sufficiently relevant or potentially useful for the particular task. For more complex repositories or tasks, this retrieval and filtering process may be delegated to a specialized skill-selection subagent operating within its own context window, allowing it to examine the task requirements and available skill descriptions without unnecessarily occupying the main agent’s working context. The resulting task-relevant skill set can then be made available to the main agent, which dynamically determines which skill to invoke for a particular subtask or execution state as the task progresses. The repository therefore serves not merely as storage, but as an organized and extensible skill-management layer supporting skill registration, discovery, retrieval, selection, reuse, and continued expansion across different agentic tasks.

## Conditions for a Skill Repository to Hold

A skill repository holds when there is an identifiable and maintained collection of reusable skills that can be systematically registered, described, discovered, retrieved, and made available to an AI agent across multiple tasks. Each stored skill $s\_i$ should have sufficient skill metadata to support discovery and compatibility assessment, such as its name, description, intended capability, applicable task or subtask types, expected inputs and outputs, dependencies, required tools, constraints, or other relevant properties. Skills admitted to the repository should also satisfy defined validation and approval requirements appropriate to the application, so that inclusion indicates that the skill has reached an acceptable state for subsequent reuse rather than representing an arbitrary temporary instruction generated during a single execution. The repository should support one or more retrieval and matching mechanisms capable of reducing the complete skill collection $\mathcal{S}$ to a task-relevant candidate set $\mathcal{S}\_{\tau}$, without requiring exact wording between a task and a skill description; semantic retrieval, metadata filtering, capability matching, ranking, and related methods can therefore be combined according to the scale and requirements of the repository. A dedicated skill-selection subagent may perform this filtering when separation of context, specialization, or repository scale makes delegation useful, but such a subagent is an optional architectural mechanism rather than a defining requirement of the repository itself. Finally, retrieval of $\mathcal{S}\_{\tau}$ should not require all retrieved skills to be activated: the main agent should be able to select and invoke an appropriate skill dynamically when the corresponding subtask, condition, or execution state arises. Under these conditions, the skill repository functions as a persistent and reusable capability source from which task-specific skill availability can be constructed without exposing the entire skill collection to every task execution.
